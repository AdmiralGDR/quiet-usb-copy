# Протокол физических USB-испытаний

Статус: **не выполнялся**. `REAL_USB_TESTS=NOT_RUN`.

Этот документ — порядок будущего испытания. Сам по себе он ничего не подключает и ничего не копирует. Запускать его можно только после отдельного разрешения владельца. Разрешение на правку исходников и на изолированные tmpfs-прогоны этот протокол не включает.

Стабильная 0.4.0 этим протоколом не объявляется, пока он не выполнен и результат не записан отдельно.

## Что нельзя делать

- Не использовать накопители с пользовательскими данными.
- Не форматировать диски и не менять системные настройки.
- Не вызывать `sudo`, `umount`, `mkfs` и не запрашивать пароль.
- Не создавать на флешке пробные файлы, если владелец отдельно не разрешил конкретный файл и его удаление.
- Не считать успешную команду `cp`, `ln` или `mv` на tmpfs доказательством файловой системы флешки.
- Не извлекать накопитель только потому, что `copy_status=SUCCESS`, контрольная сумма сошлась или `sync_status=command_ok`. Извлечение — штатная процедура операционной системы.
- Не выдёргивать источник во время записи, чтобы проверить аварию. Обрыв моделируется отдельно и не на пользовательском носителе.
- Не помечать Fedora, RHEL, РЕД ОС, FAT32, exFAT или NTFS как проверенные, если этот прогон их не запускал.

## Что подготовить

Две пустые выделенные флешки. Владелец письменно указывает, какая источник, а какая назначение. Записать модель, объём, серийный номер, если он виден без дополнительных прав, и тип файловой системы, который показала сама система после обычного подключения.

Хост: дистрибутив, ядро, `readlink -f /bin/sh`, версии `cp`, `mv`, `stat`, `find`, `awk`. Снять SHA-256 файла `quiet_usb_copy.sh` и сверить с `SHA256SUMS` того кандидата, который испытывается.

Перед подключением флешек, на этой же копии:

```sh
sha256sum -c SHA256SUMS
sh quiet_usb_copy.sh version
sh quiet_usb_copy.sh doctor
sh quiet_usb_copy.sh selftest
```

`doctor` без выбранного назначения не имеет права печатать `compat_level=SUPPORTED`. Поле `fs_gate` остаётся `UNKNOWN`, пока файловая система назначения отдельно не испытана. Успех пробы в частном каталоге состояния не делает флешку проверенной.

## Подключение

1. Подключить обе флешки и дождаться, пока система сама их откроет.
2. Записать пути корней, тип файловой системы, объём и свободное место. Команда `findmnt -D` допустима, если она уже установлена. Программа её не требует.
3. Снять контрольные суммы всех файлов, которые уже лежат на назначении. Пустая флешка даёт пустой список. Этот список — эталон «чужих» объектов.
4. Выполнить `plan` для двух корней. Копирование при этом не начинается, задание не создаётся.

```sh
sh quiet_usb_copy.sh plan "/путь/исходная" "/путь/назначение"
```

Если `plan_level=REJECT` или `check_result=REJECT`, копирование не запускать. Записать причину. `dest_link_probe=link` — короткое новое имя создалось жёсткой ссылкой и снято. `dest_link_probe=exclusive` — жёсткой ссылки нет, новое имя создаётся сразу и видно до проверки содержимого; это не атомарная публикация. `dest_link_probe=unsupported` — копирование не начинать. `dest_link_probe=UNKNOWN` — проба не выполнялась. Ни одно из этих значений не разрешает заменять существующие имена.

## Обычное копирование

Три ответа и ни одного после старта: источник, назначение, `[1]`.

```sh
sh quiet_usb_copy.sh
```

Либо без меню:

```sh
sh quiet_usb_copy.sh start "/путь/исходная" "/путь/назначение"
```

Проверки:

- `start` возвращает код 0 и печатает 0 байт в stdout и stderr.
- Меню показывает источник, назначение, направление, строки «Данные:» и «Свободно:», «Режим: бережный», «Размещение: корень назначения» или «Размещение: отдельная папка», один вердикт и короткую причину, если ограничение есть. Слов DIRECT, ROOT, SEPARATE и OK на этом экране нет.
- `[2]` показывает подробности и не создаёт задание. Возврат к тому же экрану — ещё один ответ, это уже не обычный сценарий из трёх ответов.
- После `[1]` вопросов нет. Окно, звук и уведомление самой программы не появляются. Сообщения системы к программе не относятся.
- Во время копирования открыть обычный документ на источнике и прочитать его. Записать, остаётся ли компьютер пригодным для этой работы. Это наблюдение человека, не число автоматического теста.
- Дождаться конца. Краткий итог — одна команда:

```sh
sh quiet_usb_copy.sh status
```

В терминале это несколько русских строк. `copy_status`, `verify_status` и `sync_status` в этом виде не смешиваются. Подробности:

```sh
sh quiet_usb_copy.sh status --machine
sh quiet_usb_copy.sh report --verbose
```

Затем:

```sh
sh quiet_usb_copy.sh verify
```

Сверить дерево с источником отдельной командой, которая уже есть на машине (`cmp` по файлам или свой список сумм). Записать три статуса отдельно.

Даже если все три успешны, извлечь флешку только средством операционной системы. После извлечения и повторного подключения снова сверить суммы. Этот повтор — проверка носителя, а не обещание программы.

## Отдельная папка

На назначении заранее лежит один файл, которого нет в источнике. Его сумма записана.

```sh
sh quiet_usb_copy.sh start --dest-mode separate "/путь/исходная" "/путь/назначение"
```

После завершения этот файл имеет ту же сумму. Новые данные лежат только в `QUC-<идентификатор>`. Существующие имена вне этой папки не изменены.

## Локальная копия

```sh
sh quiet_usb_copy.sh start --source-mode staged "/путь/исходная" "/путь/назначение"
```

До `stage_status=READY` исходную флешку не отключать. `status` в это время должен говорить «Источник: пока требуется.» После READY тот же `status` должен говорить «Локальная копия подготовлена и проверена.» и «Источник: больше не требуется Quiet USB Copy.» Это не разрешение выдёргивать флешку: другие программы могут её ещё использовать. Для извлечения — штатное средство операционной системы.

Поле `source_dependency=not_required` допустимо только вместе с этими фразами и только после READY. Повреждённая локальная копия даёт `source_dependency=unknown` и «Источник: статус неизвестен.» Её нельзя называть готовой.

Физически отключать источник после READY можно только если владелец отдельно разрешил этот шаг. Без такого разрешения шаг не выполняется: обрыв уже смоделирован на tmpfs, и физическое отключение здесь не считается сделанным.

Каталог локальной копии имеет режим 700. `cleanup` не вызывать, пока копия нужна для продолжения.

## Остановка и продолжение

Отдельная пара или то же назначение после очистки, снова с разрешения владельца:

```sh
sh quiet_usb_copy.sh stop
sh quiet_usb_copy.sh status
sh quiet_usb_copy.sh resume
```

`resume` ничего не печатает. Уже опубликованный файл не заменяется, если его содержимое отличается. Имя, размер и время сами по себе не доказательство.

## Что записать в протокол прогона

Для каждого шага: дата, SHA-256 скрипта, пути, тип файловой системы, `copy_status`, `verify_status`, `sync_status`, `eject_status`, код `start`, число байт его вывода, совпали ли суммы чужих файлов, появилось ли окно или уведомление программы, какая команда извлечения использовалась. Успех копирования сам по себе не записывать как разрешение вынуть флешку.

Непроверенная файловая система остаётся UNKNOWN. Один успешный `start` не переводит `fs_gate` в SUPPORTED.

## Будущее автоотключение назначения

Этот раздел не выполнялся. `AUTO_DISCONNECT_REAL_USB=NOT_RUN`. Имитация в наборе тестов сюда не переносится и остаётся MOCK.

Делать только после отдельного разрешения владельца, на двух пустых выделенных флешках, не на рабочих дисках.

1. Запустить `sh quiet_usb_copy.sh` в терминале. На экране подтверждения должна быть строка «Отключение назначения: включено», фраза «После копирования содержимое будет проверено. При успешной проверке программа попытается безопасно отключить назначение» и строка «Исходный накопитель остаётся подключённым.»
2. `[5]` меняет политику и не начинает копирование. Обычный запуск — три ответа: источник, назначение, `[1]`. Отказ от отключения — четвёртый, необязательный ответ.
3. Дождаться `copy_status=SUCCESS`, проверки конечных опубликованных файлов со статусом `checksum` или `byte` и `sync_status=command_ok`. `verify_status=size` и `verify_status=none` отключение не разрешают. Пока любого обязательного условия нет, флешку не вынимать и не считать отключение выполненным. `SUCCESS` само по себе не доказывает долговременную сохранность.
4. Смотреть `eject_status` отдельно. `power_off` записывать только если питание снято штатно. `unmounted` значит, что файловая система размонтирована, а питание не отключалось. `refused`, `unavailable`, `skipped_policy` и `unknown` не превращать в успех отключения и не переписывать успешное копирование.
5. Исходную флешку программа отключать не должна. Её можно продолжать читать.
6. Не вызывать принудительное отключение. Не вводить пароль. Если система отказала или на том же физическом устройстве занят другой раздел, оставить назначение подключённым и записать отказ.
7. После отключения `sh quiet_usb_copy.sh status` должен прочитать запись с внутреннего диска. Сообщение файлового менеджера или системы не считается дефектом программы и не обещается к подавлению.
8. Пока этот раздел не пройден на физическом устройстве, результат остаётся `UNVERIFIED`, а стабильная 0.4.0 не объявляется.

## Если кандидат ведёт себя неправильно

Остановить задание командой этой же версии. Не вызывать `cleanup`, если данные ещё нужны для `resume`. Для возврата файлов кандидата, когда копирование не выполняется, ближайший предыдущий кандидат — rc.9. Снимок самого rc.10 лежит в `rollback/0.4.0-rc.10/`.

```sh
cp rollback/0.4.0-rc.9/quiet_usb_copy.sh quiet_usb_copy.sh
cp rollback/0.4.0-rc.9/README.md README.md
cp rollback/0.4.0-rc.9/CHANGELOG.md CHANGELOG.md
cp rollback/0.4.0-rc.9/USB-PROTOCOL.md USB-PROTOCOL.md
cp rollback/0.4.0-rc.9/RELEASE-0.4.0-rc.9.md RELEASE-0.4.0-rc.9.md
cp rollback/0.4.0-rc.9/check.sh tests/check.sh
cp rollback/0.4.0-rc.9/run.sh tests/run.sh
cp rollback/0.4.0-rc.9/cases_040.sh tests/cases_040.sh
```

Контрольные суммы каталога отката проверяются командой `sha256sum -c SHA256SUMS` из этого каталога. Версия 0.3.0 не продолжает задание 0.4 с отдельной папкой, локальной копией или меткой назначения.
