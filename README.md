# Quiet USB Copy

Версия 0.4.0-rc.7 — кандидат в релиз. Стабильная версия: 0.3.0, коммит [cc2be3a](https://github.com/AdmiralGDR/quiet-usb-copy/tree/cc2be3a).

Программа копирует содержимое одной уже подключённой флешки на другую. Запуск один раз в терминале. Окно, звук и сообщения о ходе копирования программа не показывает. Версия `0.4.0-rc.7`, сборка `20261108.2`.

Пароль не нужен. Права администратора не нужны. Дополнительные пакеты ставить не нужно. Файл не запускается сам: его вызывает оболочка.

```sh
sh quiet_usb_copy.sh
```

Это кандидат, не стабильная 0.4.0. Физические USB для этой версии не подключались. Границы описаны в конце файла, изменения по версиям — в `CHANGELOG.md`. Порядок будущего испытания флешек — `USB-PROTOCOL.md`. Он не выполнялся.

## Как скопировать

1. Подключите обе флешки и дождитесь, пока система сама их откроет.
2. Запустите программу без аргументов.
3. Укажите источник, затем назначение, затем `[1]`.

Обычный сценарий — три ответа: источник, назначение, `[1]`. После `[1]` вопросов больше нет. Терминал освобождается. Одна строка: «Копирование запущено в фоне.»

На экране подтверждения отключение назначения включено, пока пользователь сам не откажется. `[5]` только меняет эту политику и не запускает копирование. Исходный накопитель программа не отключает. `start` без флага накопитель не отключает. Явный запрос для автоматизации: `start --eject-dest`.

Направление программа не угадывает. Цвет и полноэкранный режим не используются. Узкий терминал и SSH подходят: экран — обычный текст.

Список содержит только смонтированные накопители с признаком съёмности. Внутренние диски и служебные файловые системы в него не входят. Если съёмных накопителей нет, на том же экране можно ввести два абсолютных пути. Пока оба пути не выбраны, дерево файлов не обходится.

Для сценария без вопросов:

```sh
sh quiet_usb_copy.sh check "/путь/исходная" "/путь/назначение"
sh quiet_usb_copy.sh start "/путь/исходная" "/путь/назначение"
```

`start` сразу возвращает управление и ничего не печатает. Код 0 значит «задание запущено», а не «копирование уже закончилось». Итог — одна команда `status`.

Два пути без слова `start` тоже запускают копирование. Вне терминала запуск без аргументов меню не открывает. При подключении устройства копирование само не начинается.

## Экран перед запуском

Один экран, без повторения одних и тех же полей:

1. Источник и назначение.
2. Направление копирования.
3. Объём и свободное место.
4. Режим. На этом экране обычный запуск подписан «Режим: прямой».
5. Размещение: «корень назначения» или «отдельная папка». Для отдельной папки показан её путь.
6. Отключение назначения: «включено» или «выключено». Исходный накопитель остаётся подключённым.
7. Один вердикт.
8. Одна короткая причина, если копирование ограничено или запрещено.

Клавиши:

| Ответ | Действие |
|---|---|
| `[1]` | Начать копирование, если вердикт это разрешает |
| `[2]` | Подробности. Задание не создаётся |
| `[3]` | Вернуться к выбору источника и назначения |
| `[4]` | Сначала локальная копия. Пункт есть только когда она доступна |
| `[5]` | Включить или выключить отключение назначения. Копирование не начинается |
| `[0]` | Отмена. Задание не создаётся |

`[2]` не запускает копирование и не задаёт новых вопросов после старта: старта не было. Подробный список проверок на основном экране не печатается.

Вердикт не прячет ограничение под словом OK.

- Проверка не пройдена: «Вердикт: копировать нельзя.» и первая причина. `[1]` отвечает «Запуск запрещён.»
- Проверка пройдена, но есть замечание или жёсткие ссылки на назначении не проверялись: «Вердикт: можно копировать с ограничением.» и одна причина. Это не отказ и не слово «готово».

На этом кандидате план не создаёт пробный файл на флешке. Поэтому успешный экран остаётся ограниченным, даже когда копировать можно. Существующие имена не заменяются. Для отдельной папки на экране также есть фраза «Существующие файлы назначения не изменяются.» Слов DIRECT, ROOT и SEPARATE на основном экране нет.

## Короткий итог

```sh
sh quiet_usb_copy.sh status
```

Одна команда. В терминале несколько русских строк. Технические ключи туда не входят. Пример успешного итога:

```text
Копирование завершено.
Файлы: 12 из 12
Размещение: корень назначения.
Источник: больше не требуется Quiet USB Copy.
Проверка содержимого: сравнивались только размеры
Синхронизация: команда sync завершилась без ошибки. Это не разрешение извлекать накопитель.
Для извлечения используйте средства ОС.
Автоотключение назначения не выполнялось.
Режим: бережный. Задержки самой флешки возможны.
```

Пока прямое копирование ещё идёт, вместо последней фразы про источник стоит «Источник: ещё требуется для копирования.» Готовая локальная копия говорит «Локальная копия подготовлена и проверена.» и «Источник: больше не требуется Quiet USB Copy.» Это не разрешение выдернуть флешку: её могут использовать другие программы. Неподтверждённое состояние говорит «Готовность локальной копии не подтверждена.» и «Источник: статус неизвестен.» Повреждённая копия называется повреждённой и не называется готовой.

Машинное поле `source_dependency` принимает `required`, `not_required` или `unknown`. Значение `not_required` ставится только когда дальнейшие операции этого задания не читают исходный носитель. Запись в файле состояния пересчитывается при сохранении и при `status`. Подмена строки в файле ответ не меняет. Отдельного уведомления о готовности нет: смотреть `status` или `report`.

Фраза «Копирование завершено.» с точкой — только полное завершение. Неполный результат называется «Копирование завершено частично.» Остановка — «Копирование остановлено.» Неподтверждённый результат — «Результат копирования не подтверждён.» Невыполненное копирование — «Копирование не выполнено.»

Четыре состояния не смешиваются:

- копирование — своя строка и поле `copy_status`;
- проверка содержимого — своя строка и поле `verify_status`;
- синхронизация — своя строка и поле `sync_status`;
- отключение назначения — своя строка и поле `eject_status`.

`eject_status` не подменяет `copy_status`. Отказ системы отключить накопитель не делает успешное копирование неуспешным. Запись лежит в каталоге состояния на внутреннем диске, поэтому `status` читается и после того, как назначение уже недоступно.

Строка отключения бывает такой:

- «Автоотключение назначения запланировано.»
- «Файловая система назначения размонтирована. Питание не отключалось.»
- «Питание назначения отключено штатно.»
- «Автоотключение назначения не выполнялось.»
- «Средство отключения недоступно. Назначение оставлено подключённым.»
- «Система отказала в отключении. Назначение оставлено подключённым.»
- «Результат отключения неизвестен. Не извлекайте накопитель вслепую.»

Успешные копирование, проверка и `sync` сами по себе не означают, что устройство можно вынимать. Фраза «Для извлечения используйте средства ОС.» остаётся. Программа не обещает скрыть сообщения файлового менеджера, системы или аудита и не запрашивает пароль. Если безопасное действие выполнить нельзя, назначение остаётся подключённым. Исходный накопитель автоматически не отключается.

`SUCCESS` не означает, что содержимое сверено контрольной суммой. Пока её не было, проверка содержимого говорит, что сравнивались только размеры. Сумму считает `verify` или `start --verify`.

`sync_status=command_ok` значит, что выбранная команда `sync` завершилась без ошибки. Это не разрешение вынимать флешку. Перед физическим извлечением нужна штатная процедура операционной системы.

Если локальная копия дошла до `READY`, статус добавляет «Локальная копия: готова.» Если она повреждена и не используется — «Локальная копия: повреждена.» Для частичного, остановленного или отменённого копирования добавляется «Восстановление: возможно.» Если ошибка сама говорит, что носитель исчез, файл изменён или локальная копия повреждена, добавляется «Восстановление: невозможно.» Программа не объявляет повреждение, которого нет в записи задания.

Подробная диагностика:

```sh
sh quiet_usb_copy.sh report --verbose
```

Сначала тот же короткий текст, затем строка «Диагностика:» и технический журнал. Явный `--machine` оставляет только машинные строки. Когда вывод не в терминал, обычные `status` и `report` тоже машинные. Прежние поля сохранены.

Во время копирования и после ошибки программа сама ничего не печатает и не открывает окно. Всплывающих уведомлений нет.

## Остановить и продолжить

```sh
sh quiet_usb_copy.sh stop
sh quiet_usb_copy.sh resume
```

Останавливается только задание Quiet USB Copy. `resume` ничего не печатает и не держит терминал. Уже изменённый файл сам не заменяется. Одинаковое содержимое не перезаписывается. После готовой локальной копии продолжение читает её и не требует исходной флешки.

## Локальная копия

Обычный запуск читает источник во время записи. Это `direct`.

`staged` сначала собирает доступные файлы в каталог пользователя и только после проверки содержимого ставит `stage_status=READY`. Образ устройства не создаётся.

```sh
sh quiet_usb_copy.sh start --source-mode staged "/путь/исходная" "/путь/назначение"
```

В меню это пункт `[4]`, и только когда есть средство проверки содержимого, каталог данных и место. На основном экране режим при этом остаётся «прямой»: `[4]` не переписывает эту строку заранее. Отмена до подтверждения этот каталог не создаёт.

До `READY` статус говорит «Подготовка локальной копии.» и «Источник: пока требуется.» После `READY` исходная флешка этому заданию больше не нужна. Программа сама об этом не сообщает.

Каталог: `${XDG_DATA_HOME:-$HOME/.local/share}/quiet-usb-copy/staging/`, права `700`. Дерево больше 32 МиБ не копируется в `tmpfs` или `devtmpfs`.

Размер и время модификации доказательством содержимого не являются. Проверка отдельных файлов не является атомарным снимком всего дерева. Повреждённая локальная копия для переноса не используется. `cleanup` не следует вызывать, пока эта копия ещё нужна, чтобы дописать назначение.

## Непустое назначение

Обычный `start` без `--dest-mode separate` требует пустое назначение. В меню непустое назначение не копируется поверх существующих файлов: программа предлагает новую папку `QUC-<идентификатор>` и показывает путь до подтверждения.

```sh
sh quiet_usb_copy.sh start --dest-mode separate "/путь/исходная" "/путь/назначение"
```

Уже существующие файлы не удаляются и не изменяются. Символьная ссылка не принимается как каталог результата. Режим слияния не реализован: `MERGE_SAFE=NOT_IMPLEMENTED`.

## Чего программа сделать не может

Обычный сценарий оболочки не получает мгновенный согласованный снимок живой флешки. Если файл менялся и после трёх попыток размер или время не сошлись, он остаётся неподтверждённым, а задание — `UNCERTAIN`. Изменение содержимого при тех же размере и времени без контрольной суммы не обнаруживается.

Медленная флешка может на время замедлить открытие файлов. Программа снижает свой приоритет и не обещает полной незаметности.

Выход из системы может остановить фоновое задание, если так настроена сама система. Программа в автозагрузку не встаёт. Службу не создаёт.

Одинаковые пути, вложенные пути, системные каталоги и корень диска отклоняются. Если свободное место оценить нельзя, запуск отклоняется. Пока задание выполняется, второй запуск не пишет в другое место.

Два раздела одного физического диска запуск не проходят. Если диск однозначно не определён, это замечание остаётся на экране и не превращается в OK.

## Как удалить программу и её данные

Сначала посмотреть, что относится к программе:

```sh
sh quiet_usb_copy.sh cleanup --dry-run
sh quiet_usb_copy.sh cleanup
```

`--dry-run` ничего не стирает. Без ключа удаляются только завершённые служебные задания и локальная копия именно этих заданий. Выполняющееся задание и данные, нужные для продолжения, остаются. Чужие каталоги не удаляются. Процессы программа не прячет.

Затем можно удалить файл `quiet_usb_copy.sh` и служебный каталог:

```sh
rm -rf "${XDG_STATE_HOME:-$HOME/.local/state}/quiet-usb-copy"
```

Флешки при этом не трогаются. Значок, файл `.desktop` и запуск при подключении флешки не поставляются.

## Проверка на этой машине

```sh
sh quiet_usb_copy.sh version
sh quiet_usb_copy.sh doctor
sh quiet_usb_copy.sh selftest
```

`version` печатает `quiet-usb-copy 0.4.0-rc.7`, `build 20261108.2` и `sha256=`. Ожидаемая сумма этой копии скрипта:

```text
b8a9c9cbdab5cc3e17da67105eace5194661a7aababcd3e87ee6b3d5076c753b
```

`doctor` без выбранного назначения не объявляет дистрибутив проверенным и не печатает `compat_level=SUPPORTED`. На машине, где проба записи в частном каталоге прошла, а файловая система назначения не выбиралась, итог `compat_level=LIMITED`, а `fs_gate=UNKNOWN`. Неизвестная черта остаётся `UNKNOWN`. Успех команды не означает совместимость файловой системы. Проба не создаёт файл на флешке.

Три итога диагностики: `SUPPORTED`, `LIMITED`, `UNSUPPORTED`. `SUPPORTED` для всей программы требует и проверенную файловую систему назначения. Этой командой она не проверяется.

`selftest` — короткие внутренние проверки без флешек и без прав администратора.

На другом Linux, без установки пакетов и без флешек:

```sh
sha256sum quiet_usb_copy.sh
sh quiet_usb_copy.sh version
sh quiet_usb_copy.sh doctor
sh quiet_usb_copy.sh selftest
sh quiet_usb_copy.sh help
```

Сумма должна совпасть с приведённой выше. `doctor` должен отказаться называть систему полностью поддержанной, пока назначение не испытано. Полный `sh tests/run.sh` нужен только разработчику и требует уже установленные `python3` и `unshare`. Для копирования они не нужны. Нет этих команд — набор не считать пройденным.

## Для разработчика

Одна команда, она не нужна для копирования и сама пакеты не ставит:

```sh
sh tests/check.sh
```

Она проверяет синтаксис, запускает существующий набор, вызывает `version`, `doctor`, `selftest`, `plan`, `status`, `report`, `cleanup --dry-run` и неизвестную команду `rollback`, сверяет замороженные деревья в `rollback/`, если такой каталог есть в рабочей копии (в опубликованном дереве его нет), и печатает `RESULT PASS` или `RESULT FAIL`. В конце перечисляет возможности, которые эта команда не проверяла: реальный USB, FAT32, exFAT, NTFS, Fedora, RHEL, РЕД ОС, жёсткие ссылки на назначении и файловую систему назначения. Откат файла этой командой не выполняется.

Прямой набор без обёртки:

```sh
sh tests/run.sh
```

## Технические сведения

Дальше — границы, которые нужны при разборе отказа. Обычное копирование их читать не требует.

### Что именно обещает копирование

- Копируются обычные файлы, вложенные папки, скрытые имена и пустые папки. Имена переносятся как есть.
- Исходная флешка только читается. Назначение не форматируется.
- Чужой файл, который уже есть в момент публикации, не удаляется и не перезаписывается.
- `SUCCESS` ставится, когда обычные файлы, папки и ссылки перенесены, размеры сошлись и во время записи файлы не менялись.
- Неполный, прерванный или сомнительный результат остаётся со своим статусом.
- Содержимое документов в журнал не попадает.

`copy_status`: `RUNNING`, `SUCCESS`, `PARTIAL`, `FAILED`, `CANCELLED`, `INTERRUPTED`, `UNCERTAIN`.

`verify_status`: `none`, `size`, `checksum`, `byte`, `failed`, `uncertain`.

`sync_status`: `command_ok` или `unconfirmed`. Поле `copy_status` от сбоя `sync` не меняется.

Для непустого источника нужен запас: объём файлов плюс 10 процентов, но не меньше 1 МиБ.

### Публикация и временный файл

Новое имя ставится командой `ln` без `-L`. После ссылки inode назначения должен совпасть с inode временного файла. Если не совпал, имя не снимается. Иначе используется `mv -n`. Успех — только когда временное имя исчезло и, если inode был известен, inode назначения совпал. Код 0 у BusyBox `mv -n` при занятом имени не считается переносом: оба файла могут остаться. Если безопасный перенос не получился, журнал один раз получает причину, чужой объект не меняется, итог не `SUCCESS`.

Граница, которую оболочка POSIX не закрывает: GNU `mv` без `RENAME_NOREPLACE` внутри `mv -n` может проверить имя и затем переименовать. Это не доказано на FAT32 или exFAT и не объявлено защитой от одновременной подмены. Тот же пользователь, который читает каталог состояния режима 700, вне этой модели.

Временный файл открывается с запретом перезаписи. Потомок пишет в унаследованный `/proc/self/fd/3`. После закрытия дескриптора путь должен остаться тем же обычным inode. Записи командой `cp` по пути нет. Занятое временное имя не удаляется. Свой временный файл удаляется только если inode совпал. Если промежуточный каталог заменили ссылкой, удаление не идёт по этой ссылке в чужой каталог.

`mv -f` остаётся только у трёх служебных файлов внутри каталога режима 700: состояние, владелец и манифест локальной копии.

`resume` пропускает обычный файл, когда размер совпал и `cmp` подтвердил содержимое. Без `cmp` и при сохранённой сумме пропуск разрешён, только если суммы источника и назначения обе равны записи. Имя, размер и время сами по себе доказательством не являются. Ссылка, другой тип и изменённые байты остаются. Если безопасная публикация на этой машине недоступна, копирование отклоняется, а не переходит на замену.

Номер inode каталога записи живёт только в памяти процесса и в файл состояния не пишется. Метка носителя независима от сменяющегося признака задания. При `PARTIAL` метка не снимается. Пропавшая метка при продолжении заново не ставится.

### План и диагностика

```sh
sh quiet_usb_copy.sh plan "/путь/исходная" "/путь/назначение"
```

`plan` ничего не копирует и задание не создаёт. На принятом плане остаются `plan_result=OK` и `error_code=E_OK`. Ограничение видно по `plan_level`, а не по подмене кода успеха.

| Поле | Значение |
|---|---|
| `plan_level` | `READY`, `LIMITED` или `REJECT`. `UNKNOWN` сюда не подставляется |
| `publish_policy` | `no-replace` |
| `dest_link_probe` | `UNKNOWN`. План не пишет пробный файл на назначение |
| `content_tool` | `sha256`, `sha1`, `md5`, `cksum`, `cmp` или `none` |
| `checks_not_run` | `dest_hardlink`, пока проба ссылок на назначении не выполняется |

`doctor` печатает те же поля совместимости плюс три фразы: уровень, что файловая система назначения этой командой не проверялась, и что успех команды не означает совместимость файловой системы. Поля: `compat_level`, `host_write`, `fs_gate`, `posix_shell`, `find_print0`, `proc_fd`, `fd_publish`, `publish_probe`, `hash_tool`, `state_dir`, `recovery`, `data_dir`.

Проба записи одна на процесс, в частном каталоге состояния или runtime, после того как запуск уже сообщил готовность. Она не повторяется на каждый файл. Если открытый дескриптор, публикация нового имени или `find -print0` недоступны, воркер отказывается. Отсутствие каталога локальной копии само по себе прямой режим не запрещает: это `LIMITED`, не `UNSUPPORTED`.

Коды выхода: 0 команда принята, 1 отказ или сбой, 2 неверные аргументы, 70 нет программ или служебного каталога. Строки `error_code`: `E_OK`, `E_FAIL`, `E_USAGE`, `E_ENV`, `E_REJECT`, `E_NOJOB`.

Команды `rollback` у программы нет. Неизвестное слово печатает справку и завершается с кодом 2. Откат — это возврат файлов прежней версии, описанный ниже.

### Служебные данные

```text
${XDG_STATE_HOME:-$HOME/.local/state}/quiet-usb-copy/
${XDG_RUNTIME_DIR}/quiet-usb-copy/jobs/<задание>/
```

Если runtime недоступен, списки попадают в `run/jobs/` внутри каталога состояния. После завершения списки удаляются. Незавершённое задание само не стирается. Каталог состояния — режим 700.

На назначении во время копирования может появиться служебный файл `.quc-mnt-…` внутри каталога записи. При `SUCCESS` он удаляется. При незавершённом задании остаётся, чтобы `resume` узнал тот же носитель. Временное имя данных — `.quc-partial.` с номером процесса. После успеха этих имён на назначении не остаётся. Проба совместимости на флешке не создаётся.

Подмена точки монтирования после создания метки останавливает запись, и результатом не будет `SUCCESS`. Подмена до создания метки этим способом не обнаруживается. Совпадение номера устройства после нового монтирования на тот же путь само по себе носитель не доказывает.

Обязательные команды: `find`, `stat`, `awk`, `od`, `tr`, `mkdir`, `rm`, `rmdir`, `mv`, `ln`, `chmod`, `date`, `readlink`, `sleep`, `cat`, `cp`, `grep`, `dirname`, `basename`.

Необязательные: `flock`, `findmnt`, `setsid`, `nohup`, `nice`, `renice`, `ionice`, `sync`, `touch`, `sha256sum`, `sha1sum`, `md5sum`, `cksum`, `cmp`.

Не используются `rsync`, `pv`, `jq`, сетевые запросы и установка пакетов. Новых обязательных команд в 0.4.0-rc.7 нет. `udisksctl`, `tar` и `gzip` для обычного копирования не нужны. Если `udisksctl` есть, программа может им размонтировать только назначение и только после полного успеха, без `--force` и без запроса пароля. Отсутствие этой программы копирование не запрещает. `stat` вызывается как GNU `stat -c` и `stat -f`. Для `/proc/self/fd/N` используется `stat -L`.

Профиль `gentle` — приоритет 19 и, если есть `ionice`, класс best-effort с уровнем 7 только у своего процесса. Другое имя профиля отклоняется.

### Файлы, которые обрабатываются иначе

- Символьная ссылка копируется как ссылка. Если назначение не умеет хранить ссылки, итог `PARTIAL`.
- Канал, сокет и файл устройства на назначении не создаются. Итог `PARTIAL`.
- Вложенный диск внутри флешки не копируется. Итог не `SUCCESS`.
- Жёсткая ссылка становится отдельной копией файла.
- Расширенные атрибуты и списки доступа не переносятся.
- На типе `vfat`, `msdos`, `fat` или `msdosfs` файл больше 4 ГиБ не копируется. Реальная FAT32 не подключалась.
- Имена, которые FAT не принимает, пропускаются. Регистронезависимое совпадение на FAT не испытывалось и остаётся неизвестным.
- На ext4 каталог `lost+found` делает назначение непустым.

### Матрица совместимости

Проверено на одной машине, во временных каталогах. Это не список поддержанных дистрибутивов и не список файловых систем.

| Объект | Что сделано | Итог |
|---|---|---|
| Pop!_OS 24.04 LTS, ядро `7.2.6-76070206-generic`, dash 0.5.12, GNU coreutils 9.4, findutils 4.9.0 | полный `sh tests/check.sh` кандидата rc.7, 128 из 128 | кандидат ограничен: `compat_level=LIMITED`, `fs_gate=UNKNOWN` |
| BusyBox 1.36.1 | отдельные пробы `mv -n` и записи в дескриптор внутри набора | участие в пробах, не сертификация BusyBox |
| bash, busybox sh | синтаксис проверялся на прежних версиях | сценарии целиком на них не гонялись для этой версии |
| shellcheck 0.9.0 | `shellcheck -s sh quiet_usb_copy.sh` | без замечаний на этой копии |
| Fedora, RHEL 7/8/9, РЕД ОС 7.3/8 | не запускались | не проверено |
| FAT32, exFAT, NTFS, физический ext4, USB | не подключались | не проверено. Замер на tmpfs — не замер USB |
| Жёсткие ссылки на назначении | план их не создаёт | `dest_link_probe=UNKNOWN` |

Двоичные файлы GNU coreutils 8.22, 8.30 и 8.32 здесь не запускались. Номер версии не доказывает, что `sync -d -- FILE` принят. Программа каждый запуск пробует ту команду, которой потом пользуется. Если обе формы отклонены, копирование продолжается, а `sync_status` остаётся `unconfirmed`.

По исходным текстам меток GNU coreutils, без запуска дистрибутивов: в 8.22 и 8.23 команда имеет вид `sync [OPTION]` и не принимает файл. В NEWS метки 8.32 сказано, что аргумент-файл появился в 8.24. Пакеты RHEL и РЕД ОС могут отличаться от этих меток.

### Известные ограничения

- POSIX-оболочка не защищает от подмены того же inode тем же пользователем между проверкой и действием.
- `mv -n` на GNU без `RENAME_NOREPLACE` остаётся окном проверки и переименования.
- Файловая система назначения этой сборкой не подтверждена. Безопасная запись, которую проба не смогла выполнить, отклоняется.
- `sync` не разрешает извлечение.
- Автоотключение назначения на физическом USB не проверялось. Успешная имитация не является проверкой устройства. Если нужную проверку выполнить нельзя, программа накопитель не отключает.
- Архивный режим в этот кандидат не входит. `tar` и `gzip` не становятся частью обычного копирования.
- Метка не видит подмену носителя до своего создания.
- Номер inode каталога не переживает остановку процесса и не годится как доказательство на FAT после переподключения.
- Чтение каталога состояния режима 700 тем же пользователем вне модели.
- `MERGE_SAFE` не реализован.
- Стабильная 0.4.0 не объявляется.

### Откат

Откат — возврат файлов прежней версии, пока фоновое копирование не выполняется. Команды `rollback` у программы нет.

Предыдущий опубликованный кандидат — 0.4.0-rc.5, коммит `1090f43`, сборка `20261101.3`, сумма скрипта в этом коммите `946e9d86c9508631fc5c00bd9b3c59b611dcb5e9611ef8c551be45b6340f2593`. Из клона репозитория:

```sh
git checkout 1090f43 -- quiet_usb_copy.sh README.md CHANGELOG.md USB-PROTOCOL.md tests/check.sh tests/run.sh tests/cases_040.sh
```

После этого `sh quiet_usb_copy.sh version` печатает `quiet-usb-copy 0.4.0-rc.5` и `build 20261101.3`. Файл `.github/workflows/ci.yml` версия rc.5 не читает.

Стабильная версия 0.3.0 — коммит `cc2be3a`, сборка `20261029.2`, сумма скрипта в этом коммите `9478626853f4eeace06b02a02cfff3d9046af74fb606617f1b6d4beb13aec127`. Из клона репозитория:

```sh
git checkout cc2be3a -- quiet_usb_copy.sh README.md tests/run.sh tests/pty_menu.py tests/tree_equal.py tests/eacess_preload.c
```

После этого `sh quiet_usb_copy.sh version` печатает `quiet-usb-copy 0.3.0` и `build 20261029.2`. Файлы `CHANGELOG.md`, `USB-PROTOCOL.md`, `tests/cases_040.sh` и `tests/check.sh` версия 0.3.0 не читает.

Задание 0.4 с отдельной папкой, локальной копией или меткой назначения версией 0.3.0 продолжать нельзя. Перед таким откатом остановите задание командой 0.4 и вызовите `cleanup`, если локальная копия больше не нужна.

Это дерево с правками набора — полный `sh tests/check.sh`, 128 из 128, `RESULT PASS`, на Linux с GNU coreutils 9.7; на Pop!_OS оно не запускалось.
